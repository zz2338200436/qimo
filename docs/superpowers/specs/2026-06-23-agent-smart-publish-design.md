# Agent 智能发布作业设计

日期：2026-06-23

## 背景

教师在题库或 AI 出题结果页面输入“把这个题发布到班级”“全部随机”时，当前 Agent 会直接要求补充课程、标题、截止时间、满分。这个行为来自固定缺槽规则和执行层硬校验，导致体验像表单校验器，而不是助教。

目标不是删除发布安全限制，而是把聊天理解层改成可推断、可追问、可确认，最终执行层继续严格校验。

## 目标

- 支持“这个题”“这些题”“全部随机”等自然表达。
- 前端向 Agent 提供当前页面上下文，例如当前题目、题库筛选条件、当前课程或班级。
- Agent 能为标题、满分、截止时间生成合理默认值。
- Agent 只追问真正无法确定且会影响发布对象的字段，例如班级、课程。
- 写操作执行前仍生成确认卡片，展示所有自动推断和默认字段。
- `AssignmentPublishTool` 保留最终硬校验，避免缺字段或错误权限导致误发布。

## 非目标

- 不让 Agent 在没有确认卡片的情况下直接发布作业。
- 不假装知道当前班级；如果页面上下文没有班级，必须追问或展示候选项。
- 不一次性重做全部 Agent 意图系统。
- 不把发布考试、通知、课程创建等其他写操作一起智能化；它们可后续复用同一模式。

## 推荐方案

采用“页面上下文 + 发布草稿 + 最终确认”的增量设计。

### 1. 页面上下文

前端聊天请求增加 `context` 字段，用于传当前页面的可见业务上下文。

示例：

```json
{
  "page": "teacher-question-bank",
  "selectedQuestionIds": [91022],
  "selectedQuestionScore": 2,
  "selectedQuestionType": "TRUE_FALSE",
  "selectedQuestionContent": "服务注册中心通常保存服务实例的地址、端口和健康状态等信息。",
  "questionFilter": {
    "courseId": null,
    "knowledgePointId": 9003,
    "difficulty": "中等",
    "type": "TRUE_FALSE"
  },
  "currentCourseId": null,
  "currentClassId": null
}
```

后端只使用白名单字段，忽略未知字段。

### 2. 发布草稿

Agent 将发布作业相关对话维护为草稿，而不是每轮都重新从用户文本里抽完整字段。

草稿字段：

```json
{
  "intent": "PUBLISH_ASSIGNMENT",
  "selectionMode": "SELECTED_QUESTIONS",
  "questionIds": [91022],
  "courseId": null,
  "classIds": [],
  "title": "服务注册中心判断题练习",
  "maxScore": 2,
  "dueDate": "2026-06-30 23:59:59",
  "content": "题目内容或题目引用"
}
```

草稿优先级：

1. 用户本轮明确输入。
2. 当前会话 pending slots。
3. 前端页面上下文。
4. 系统默认值。

### 3. 默认值策略

- 标题：单题用题目关键词生成，如“服务注册中心判断题练习”；随机组卷用“随机题库练习”。
- 满分：单题取题目分值；多题累加；随机组卷默认 100 分或按抽题规则计算。
- 截止时间：默认 7 天后 23:59:59。
- 课程：只有当前上下文或课程名能唯一解析时才自动补。
- 班级：只有当前上下文或用户明确指定时才自动补；否则追问。

### 4. 追问策略

缺少发布对象时，只问发布对象，不重复要求所有字段。

示例：

```text
我已选择当前这道题，标题、满分和截止时间可以自动生成。还需要选择发布班级。
```

如果有候选班级：

```text
请选择发布班级：软件2301、软件2302、计科2301。
```

如果没有候选：

```text
我还不知道可发布的班级，请先提供课程名或班级名。
```

### 5. 确认卡片

字段齐全后，仍使用现有确认卡片。卡片要展示：

- 发布班级
- 题目范围
- 标题
- 截止时间
- 满分
- 自动推断字段标记

用户确认后才调用发布工具。

### 6. 最终执行校验

执行层继续要求：

- `title`
- `courseId`
- `dueDate`
- `maxScore`

如果后续支持班级定向发布，执行层还应要求 `classIds` 或通过课程关联确定可见学生范围。权限校验仍由教师课程所有权和班级关联关系完成。

## 实现范围

第一阶段只覆盖教师发布作业：

- `AgentChatRequestDTO` 增加 `context`。
- 前端 `agent-chat-panel.js` 发送页面上下文。
- 新增或扩展上下文合并逻辑，把“这个题”“全部随机”转换成发布草稿。
- 调整 `AgentSlotRequirementService` 的发布作业缺槽规则：默认字段不再阻塞，只阻塞不可推断的课程或班级。
- 调整提示语，输出下一步追问，而不是固定缺字段列表。
- 保持 `AssignmentPublishTool` 的执行层校验。

## 测试

- 单元测试：发布作业缺槽规则。
- 单元测试：页面上下文合并到发布草稿。
- 单元测试：“这个题发布到班级”只追问班级。
- 单元测试：“全部随机”识别为随机题目发布草稿。
- 集成测试：字段齐全时生成确认卡片，不直接发布。
- 浏览器 smoke：题库页面选择题目后，聊天输入“把这个题发布到班级”。

## 验收标准

- 用户说“把这个题发布到班级”时，不再回复“缺课程、标题、截止时间、满分”。
- 如果没有班级上下文，Agent 只追问班级或课程。
- 用户说“全部随机”时，Agent 能理解为随机题库发布草稿。
- 自动生成的标题、满分、截止时间会在确认卡片中展示。
- 没有用户确认时，系统不会创建作业。
