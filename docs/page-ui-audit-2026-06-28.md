# 页面 UI / UX 审计报告

日期：2026-06-28  
范围：`major_assignment/src/main/resources/static`

## 审计范围

本次页面审计覆盖四组页面：

- 登录与入口页
- 学生端页面
- 教师端页面
- AI 助手相关页面

审计方式以源码结构、静态 HTML/CSS/JS 交互逻辑为主，并结合现有页面壳层、组件复用和验证脚本进行判断。未包含真实浏览器人工操作和线上接口时延验证。

## 全站共性问题

### P0 壳层导航状态模型冲突

当前侧边栏将 `collapsed` 同时用于：

- 桌面端收起侧边栏
- 移动端打开抽屉导航

再叠加：

- `common-ui.js` 的公共逻辑
- `sidebar-nav.html` / `teacher-sidebar-nav.html` 组件内逻辑
- 多个页面自己的局部侧边栏逻辑

结果是导航语义冲突、状态不同步、移动端体验不稳定。这是全站最高优先级问题。

### P1 设计系统不统一

全局样式、登录页、学生页、教师页、AI 页各自维护一套视觉和交互规则，主要体现在：

- 字体栈不统一
- 按钮和输入框状态不统一
- 侧边栏与顶部栏实现不统一
- loading / empty / error 反馈样式不统一
- 学生端与教师端主题继承不稳定

### P1 状态反馈质量不一致

多个页面存在以下问题：

- 只有顶部 alert，没有字段级反馈
- 批量操作缺少确认、撤销或摘要
- 服务状态是静态文案，不是真实运行态
- 空状态没有下一步 CTA
- 历史/筛选/批改流缺少“当前作用范围”提示

## 分组结论

### 1. 登录与入口页

主要问题：

- 首页只是“学生/教师二选一”，信息层级较弱
- 登录表单的错误反馈不够细
- 学生/教师验证码规则不一致
- 空链接文案会制造预期落差
- 导航与下拉组件复用性、可访问性不够稳

高优先级建议：

- 强化入口页角色差异和 CTA 层级
- 统一登录表单校验与错误反馈模式
- 补全字段级提示、聚焦、aria 关联

### 2. 学生端页面

主要问题：

- 仪表盘更像数据看板，不像学习工作台
- 作业/考试/成绩页信息密度高但层级不足
- 通知、设置、课程页的交互成熟度不一致
- 移动端导航问题会影响所有学生页

高优先级建议：

- 首页增加“下一步该做什么”的主任务入口
- 合并和简化作业页的 tab / 筛选 / 状态组织
- 统一学生端的卡片、表单、列表和空状态系统

### 3. 教师端页面

主要问题：

- `teacher-courses.html` 与 `teacher-assignments.html` 承担了过多后台工作流
- 预警、筛选、批改缺少清晰的当前上下文提示
- 知识点页把分析与管理混在一起
- 多页在移动端仍保留桌面式“收起侧栏 + 内容右移”思路

高优先级建议：

- 把重页面拆成“总览页 + 子任务页”结构
- 给筛选结果、处理队列、批改范围增加固定摘要
- 统一教师端顶栏、页头、表格、表单与弹窗语义

### 4. AI 助手页面

主要问题：

- 历史面板控制器存在全局绑定风险
- 历史列表默认选中第一条，而不是当前会话
- 输入区人体工学一般，发送中直接禁用输入框
- 教师页同时存在聊天模式与结果模式双心智模型
- 页头“服务已开通”是静态文案，不反映真实状态

高优先级建议：

- 重构会话历史的信息架构
- 统一聊天、结果、历史三者关系
- 优化输入区规则提示、状态反馈与移动端布局

## 建议修复顺序

1. 统一侧边栏和移动端导航壳层
2. 统一全站设计 token 与通用反馈组件
3. 拆分教师端重页面
4. 优化 AI 页面的人体工学与会话历史

## 当前执行计划

本轮先落地第 1 项：

- 统一侧边栏状态模型
- 移除页面级重复导航控制
- 固化移动端抽屉与桌面收起语义
- 增加导航行为验证脚本

## 局限说明
