# 智能学习辅助系统 RAG 外挂知识库建设方案

## 1. 文档用途

本文档用于指导智能学习辅助系统后续接入 RAG 外挂知识库能力。它定义知识库的建设目标、资料格式、处理流程、权限边界、Agent 集成方式和第一阶段验收标准。

RAG 外挂知识库用于支撑课程资料问答、平台功能说明、知识点解释和学习建议生成，不用于替代业务数据库查询。课程、作业、考试、成绩、通知、知识点列表等结构化数据仍然应通过 Agent Tool 调用后端服务获取。

## 2. 系统定位

智能学习辅助系统面向教师和学生两个角色，核心目标是把课程管理、作业管理、考试管理、学习分析和 AI 助手能力整合到同一平台中。

教师可以通过系统管理课程、发布作业、发布考试、批改提交、查看学生学习情况，并通过 AI 助手快速查询教学相关数据。

学生可以通过系统查看课程、完成作业、参加考试、查看通知、查看学习统计，并通过 AI 助手获得学习路径建议和知识点解释。

## 3. AI 助手能力边界

AI 助手分为两类能力：业务工具调用和 RAG 知识问答。

业务工具调用适合处理明确、结构化、需要权限校验的数据操作。例如查询课程列表、查询作业、查询考试、查询通知、查询课程知识点。

RAG 知识问答适合处理解释型、资料型、辅助学习型问题。例如解释某个知识点、总结课程资料、说明平台操作流程、根据课程文档生成学习建议。

AI 助手不应使用 RAG 直接编造业务数据。只要问题涉及实时课程、作业、考试、成绩、通知或学生名单，就应优先走业务工具。

## 4. 建设目标

RAG 外挂知识库第一阶段建设目标如下：

- 支持导入 Markdown 格式的课程资料、平台说明和知识点说明。
- 支持按章节和自然段切分文档，并保留文档来源、章节标题、课程范围和角色范围等元数据。
- 支持教师和学生在 AI 助手中提出知识解释类问题。
- 支持基于检索片段生成答案，并在回答中展示引用来源。
- 支持与现有 Agent Tool 共存，避免用 RAG 替代权威业务接口。
- 支持后续扩展 PDF、DOCX 等资料导入能力。

## 5. RAG 适合回答的问题

RAG 适合回答以下类型的问题：

- “什么是服务注册与发现？”
- “Spring Cloud Gateway 在本系统中负责什么？”
- “如何理解配置中心的作用？”
- “学生应该如何使用 AI 助手复习课程知识点？”
- “教师如何通过 AI 助手辅助分析学生学习情况？”
- “请根据课程资料解释作业中的知识点。”

这些问题通常不要求访问实时数据库，而是要求基于文档、课程资料或平台说明进行解释。

## 6. RAG 不适合直接回答的问题

RAG 不应直接回答以下问题：

- “张三这门课考了多少分？”
- “课程 ID 91005 有哪些作业？”
- “今天有哪些考试需要发布？”
- “帮我删除这条通知。”
- “查询云计算技术课程的学生名单。”

这些问题涉及实时业务数据、权限边界或写操作，应由 Agent Tool 调用对应服务完成。

## 7. 总体架构

RAG 外挂知识库建议作为 Agent 能力的只读扩展，不直接暴露给前端页面。

整体结构如下：

```text
前端 AI 助手
  -> gateway
  -> agent-service
  -> 意图识别与权限校验
  -> Tool 查询 或 RAG 查询
  -> 文档检索
  -> LLM 生成答案
  -> 返回答案与引用来源
```

其中 Agent 负责判断用户问题应进入 Tool 链路还是 RAG 链路。RAG 只处理知识解释类问题；业务查询、写操作和需要确认的操作仍然由 Tool 链路处理。

## 8. 推荐的 RAG 数据流

RAG 查询流程建议如下：

1. 用户在 AI 助手输入自然语言问题。
2. Agent 先识别问题类型。
3. 如果是业务查询，调用对应 Tool。
4. 如果是知识解释，进入 RAG 检索流程。
5. RAG 按课程、角色、资料可见范围过滤文档。
6. 系统检索相关片段。
7. 大模型基于检索片段生成答案。
8. 返回答案时附带引用来源。

引用来源至少应包含文档标题、章节标题、课程 ID 或资料 ID。

## 9. 知识库文档格式

第一阶段建议优先使用 Markdown 文档作为知识源。

Markdown 文档具有清晰的标题层级，便于按照章节切分。标题、列表、代码块和表格都可以保留较好的语义结构。

PDF 文档可以作为导入来源，但建议先转换成 Markdown，再经过清洗后入库。直接对 PDF 做切分容易受到页眉、页脚、换行和表格错位影响。

推荐流程是：

```text
PDF 或 DOCX 原始资料 -> Markdown 转换 -> 内容清洗 -> 文档切分 -> 向量化 -> RAG 检索
```

第一阶段不建议直接把 PDF 作为主知识源。PDF 可以作为原始导入资料，但入库前应转换为 Markdown 或结构化文本。

## 10. 文档目录建议

建议在项目中建立如下知识库目录：

```text
docs/rag/
  courses/
    distributed-framework-technology.md
  platform/
    student-guide.md
    teacher-guide.md
  knowledge-points/
    spring-cloud-basics.md
    microservice-governance.md
```

其中：

- `courses` 存放课程介绍、章节说明和学习目标。
- `platform` 存放平台使用说明和角色操作指南。
- `knowledge-points` 存放可独立检索的知识点解释材料。

## 11. 分块策略

每个知识片段应尽量围绕一个清晰主题。

建议以二级标题或三级标题作为主要切分边界。每个分块长度可以控制在 300 到 800 中文字之间。

如果章节很短，可以合并相邻章节。如果章节很长，应按自然段继续拆分。

每个分块应保留以下元数据：

- `documentId`
- `documentTitle`
- `sectionTitle`
- `courseId`
- `knowledgePointId`
- `roleScope`
- `sourceType`
- `updatedAt`

这些元数据用于权限过滤、引用展示和后续排查。

## 12. 元数据模型建议

每个入库文档建议维护如下字段：

| 字段 | 说明 |
| --- | --- |
| `documentId` | 文档唯一标识 |
| `title` | 文档标题 |
| `sourceType` | 来源类型，例如 `markdown`、`pdf-converted`、`manual` |
| `courseId` | 关联课程 ID，可为空 |
| `knowledgePointId` | 关联知识点 ID，可为空 |
| `roleScope` | 可见角色，例如 `teacher`、`student`、`all` |
| `createdBy` | 上传或维护人员 |
| `updatedAt` | 最近更新时间 |

每个分块建议维护如下字段：

| 字段 | 说明 |
| --- | --- |
| `chunkId` | 分块唯一标识 |
| `documentId` | 所属文档 ID |
| `sectionTitle` | 所属章节标题 |
| `content` | 分块正文 |
| `embedding` | 向量表示 |
| `tokenCount` | 分块长度 |
| `sortOrder` | 原文顺序 |

## 13. 权限与安全边界

RAG 检索必须遵守用户身份和课程范围。

教师只能检索自己有权限管理的课程资料。学生只能检索自己已加入课程或公开课程的资料。

如果资料只对教师可见，学生提问时不应返回该资料内容。

如果问题涉及跨课程、跨班级或跨学生数据，系统必须先做权限校验，而不是直接进入 RAG。

## 14. Agent 集成边界

建议新增只读意图 `QUERY_RAG_KNOWLEDGE`，用于承接知识解释、平台说明和课程资料问答。

该意图不执行写操作，不触发确认流程，不修改业务数据。

Agent 判断逻辑建议如下：

- 用户询问实时业务数据时，走 Tool。
- 用户询问概念解释、学习建议、平台说明时，走 RAG。
- 用户问题同时包含业务数据和知识解释时，先走 Tool 获取权威数据，再走 RAG 生成解释。

示例：

```text
问题：列出云计算技术课程的知识点，并解释服务注册与发现。
处理：先调用课程知识点 Tool，再使用 RAG 检索服务注册与发现相关资料。
```

## 15. 平台功能说明：课程管理

课程管理用于维护课程基础信息、班级关系和教师授课范围。

教师可以查看自己负责的课程，并在课程维度下管理作业、考试、知识点和学习分析。

学生可以查看自己已加入的课程，并进入课程页面查看作业、考试、通知和学习统计。

在 AI 助手中，课程信息通常作为上下文使用。例如用户提到“云计算技术课程”时，Agent 可以先解析课程名称，再补全课程 ID。

## 16. 平台功能说明：知识点管理

知识点是连接课程内容、作业题目、考试题目和学习分析的关键对象。

课程知识点可以用于描述学生应该掌握的学习目标。例如“服务注册与发现”“配置中心”“API 网关”“服务熔断”“消息队列”等。

教师可以通过知识点组织课程内容，也可以根据学生在作业和考试中的表现查看知识点掌握情况。

AI 助手查询课程知识点时，应调用课程服务提供的业务接口，而不是从 RAG 文档中猜测当前课程有哪些知识点。

## 17. 平台功能说明：作业管理

作业管理用于教师发布课程作业、学生提交作业、教师批改作业和系统统计作业完成情况。

作业可以关联课程和知识点。关联知识点后，系统可以把学生的作业表现沉淀到学习分析中。

AI 助手可以辅助教师查询作业状态、查看提交情况、整理待批改任务。涉及真实作业数据时，应通过作业服务查询。

RAG 可以用于解释作业相关知识点、说明作业要求、总结作业评分标准。

## 18. 平台功能说明：考试管理

考试管理用于教师创建考试、发布考试、管理题目、学生参加考试和系统统计考试结果。

考试题目可以关联知识点。系统可以根据考试结果分析学生对不同知识点的掌握情况。

AI 助手可以辅助教师查询考试发布状态、学生考试情况和题目知识点分布。

RAG 可以用于解释考试涉及的概念、帮助学生复习相关知识，但不应直接透露未公开试题答案。

## 19. 平台功能说明：学习分析

学习分析用于整合作业、考试和课程行为数据，形成学生学习状态视图。

学习分析可以展示学生对不同知识点的掌握情况、近期成绩趋势、作业完成情况和预警信息。

教师可以通过学习分析发现需要重点辅导的学生。学生可以通过学习分析了解自己的薄弱知识点。

AI 助手可以把结构化学习分析数据转化为自然语言建议。例如“你在服务熔断和配置中心两个知识点上表现较弱，建议先复习课程第 3 章和第 4 章”。

## 20. 课程知识点：服务注册与发现

服务注册与发现是微服务架构中的基础能力。

在多服务系统中，服务实例可能动态启动、停止或扩容。服务注册中心用于保存服务实例地址，服务消费者通过注册中心查找目标服务。

在本系统中，注册中心用于支撑 gateway、auth-service、course-service、assignment-service、exam-service、agent-service 等服务之间的发现和调用。

服务注册与发现的价值是减少硬编码地址，提高服务扩展能力，并为负载均衡提供基础。

## 21. 课程知识点：API 网关

API 网关是客户端访问后端微服务的统一入口。

在本系统中，Gateway 负责统一路由、鉴权、限流、跨域处理和 TraceId 注入。

前端页面不需要直接调用每一个业务服务，而是统一访问网关路径。网关再根据路由规则把请求转发到对应服务。

这种设计可以减少前端对后端服务拓扑的感知，也方便统一治理安全、流量和日志。

## 22. 课程知识点：配置中心

配置中心用于集中管理不同服务的配置。

在本系统中，Config Server 负责管理 gateway、auth-service、course-service、assignment-service、exam-service、agent-service 等服务的运行配置。

配置中心可以降低多服务本地启动和部署时的配置漂移风险。

常见配置包括服务端口、数据库连接、注册中心地址、限流参数、熔断参数和环境 profile。

## 23. 课程知识点：服务熔断

服务熔断用于防止下游服务异常时故障继续放大。

当某个服务持续失败或响应过慢时，熔断器可以暂时阻断调用，并快速返回降级结果。

在教学平台中，熔断可以保护核心接口。例如考试提交、AI 生成和 Agent 调用都需要避免异常流量拖垮系统。

熔断不是解决业务错误的手段，而是系统稳定性保护机制。

## 24. 课程知识点：消息队列

消息队列用于解耦异步任务。

在本系统中，RabbitMQ 可以用于通知发送、学习分析事件、作业提交事件和考试完成事件。

使用消息队列后，核心业务接口可以先完成主流程，再把后续统计、通知或分析任务交给异步消费者处理。

这种方式可以降低接口响应时间，并提高系统的扩展能力。

## 25. 学生使用 AI 助手的建议

学生使用 AI 助手时，可以优先提出学习相关问题。

例如：

- “解释一下服务注册与发现。”
- “我应该如何复习 API 网关？”
- “根据我的薄弱知识点给出复习建议。”
- “总结配置中心的作用。”

如果问题涉及个人成绩或作业状态，AI 助手应先调用业务工具获取真实数据，再结合 RAG 文档生成解释。

## 26. 教师使用 AI 助手的建议

教师使用 AI 助手时，可以优先提出教学管理和学情分析相关问题。

例如：

- “查看课程 ID 91005 的知识点。”
- “查询云计算技术课程知识点。”
- “总结本课程学生常见薄弱知识点。”
- “解释服务熔断这一知识点，生成课堂讲解提纲。”

其中前两个问题属于业务查询，应走 Tool。后两个问题属于解释和生成，应走 RAG 或 Tool + RAG 混合链路。

## 27. Tool 与 RAG 混合示例

用户问题：

```text
列出云计算技术课程的知识点，并解释服务注册与发现。
```

推荐处理流程：

1. Agent 识别到问题包含课程知识点查询和知识解释。
2. 先调用 Tool 查询课程知识点列表。
3. 再使用 RAG 检索“服务注册与发现”相关资料。
4. 最终回答中同时展示课程知识点列表和概念解释。

这种模式可以同时保证业务数据准确和解释内容丰富。

## 28. 回答引用格式

RAG 回答应附带引用来源。

推荐格式：

```text
参考来源：
1. 《智能学习辅助系统 RAG 外挂知识库建设方案》- 课程知识点：服务注册与发现
2. courseId=91005, knowledgePointId=service-discovery
```

如果没有检索到可靠资料，AI 助手应明确说明“当前知识库中没有找到足够依据”，而不是编造答案。

## 29. 第一阶段验收标准

第一阶段 RAG 接入可以用以下标准验收：

- 能导入 Markdown 文档。
- 能按标题和段落切分文档。
- 能保存文档片段和元数据。
- 能根据用户问题检索相关片段。
- 能返回带引用来源的答案。
- 能区分业务 Tool 查询和 RAG 知识问答。
- 不会用 RAG 绕过权限查询业务数据。

如果以上标准满足，就可以作为课程项目演示中的 RAG 最小闭环。

## 30. 后续扩展计划

第二阶段可以增加 PDF 和 DOCX 导入能力。

扩展流程建议如下：

1. 上传 PDF 或 DOCX 原始资料。
2. 转换为 Markdown 或结构化文本。
3. 清理页眉、页脚、目录、重复分页信息。
4. 人工或程序校验转换质量。
5. 进入统一的 Markdown 切分和向量化流程。

第三阶段可以增加知识库管理页面，支持教师上传课程资料、查看分块结果、重新向量化文档和下线过期资料。
